# GSN AI 推論服務：2× H100 + 1× RTX 5090 模型配置與定價規劃

> 目標：在 gsnshop.amaryllo.us 加入類似 fireworks.ai 的「預付儲值 → 依 token 計費」AI API 服務。
> 硬體：H100 伺服器（2 張 NVIDIA H100 80GB，以 SXM 估算；若為 PCIe 版，吞吐量約打 7–8 折）＋ RTX 5090 伺服器（1 張 GeForce RTX 5090 32GB）。
> 本文的吞吐量為依公開 benchmark 推估的數字，上線前需用 vLLM `benchmark_serving.py` 實測後再校正價格。

## 1. 設計原則

1. **只放 MoE 或小模型當 Serverless。** 這套硬體無法承載 DeepSeek-V3/R1（671B）、Qwen3-235B 這類大模型。
   MoE 模型（gpt-oss-120b 每 token 只啟用 5.1B、Qwen3-30B-A3B 只啟用 3B）在單卡上就有很高的並發吞吐量，最划算。
2. **大模型放 H100，小模型放 RTX 5090。** 5090 只有 32GB，適合 20B 以下模型、Embedding、Rerank 與語音；
   把這些搬到 5090 後，兩張 H100 的記憶體可全部留給大模型的 KV cache，長上下文與高並發都更穩。
3. **每張卡獨立服務，不做 tensor parallel。** 單卡放得下的模型就不跨卡，故障時只影響部分模型，也比較好排程。
4. **常駐、無冷啟動。** 模型數量少但全部常駐，Playground 和 API 第一個請求就很快。
5. **只賣 Serverless token。** 不出租整張 GPU，也不提供微調，所有卡都用來服務共享的 API 流量。
6. **定價只看模型，不看機器。** 同一個模型不論由 H100 或 RTX 5090 處理，價格完全一樣；機器只影響內部排程，客戶不需要選。

### 模型與機器適用表

| 模型 | H100 | RTX 5090 | 說明 |
|---|---|---|---|
| gpt-oss-120b | 運行中 | 不適用 | 權重 61GB，超過 5090 的 32GB |
| Qwen3-30B-A3B-Instruct-2507 | 運行中 | 不適用 | FP8 權重 31GB，5090 放不下 KV cache |
| gpt-oss-20b | 可支援 | 運行中 | 5090 原生支援 FP4，單一請求速度與 H100 相近 |
| Qwen2.5-VL-7B-Instruct | 運行中 | 可支援 | 5090 滿載時的備援 |
| BGE-M3 / BGE-Reranker-v2-M3 | 可支援 | 運行中 | |
| Whisper large-v3-turbo | 可支援 | 運行中 | |

「可支援」代表該機器故障或滿載時，Gateway 可以把流量切過去（容量會變小，但價格不變）。

- 推論引擎：vLLM（OpenAI 相容），前面放一層 API Gateway 做金鑰驗證、速率限制、計費與跨機器路由（建議 LiteLLM Proxy 或自寫 FastAPI + Redis）。
- 同一張卡上的多個行程靠 `--gpu-memory-utilization` 切分記憶體；H100 也可以改用 MIG，隔離更好但配置較死。5090 不支援 MIG。
- gpt-oss-20b 的上下文限制在 32K，避免單一長請求吃光 5090 的 KV cache。

- **批次 API 5 折**：24 小時內完成，用離峰時段的閒置算力，提高夜間利用率。
- **快取輸入半價**：vLLM 開啟 prefix caching，重複的 system prompt 幾乎不耗算力。

- 價格約為大型雲端推論商同級模型的 1.0–1.2 倍。溢價的理由是在地支援、新台幣發票、資料不出自有機房；如果要搶市佔，可直接降到與市場持平。

## 5. 容量與損益估算

**成本假設**：
- H100 一張購入約 US$25–30K，3 年攤提，加上電費（~700W × PUE 1.4）與機房費用，全包約 **US$1.6–2.0 / GPU 小時**，2 張每月約 **US$2,300–2,900**。
- RTX 5090 伺服器（顯卡約 US$2–3K＋主機約 US$2K）3 年攤提，加上電費（~600W × PUE 1.4）與機房費用，每月約 **US$250**。
- 合計每月約 **US$2,550–3,150**。

**吞吐量估計（vLLM，高並發）**：

| 模型 | 機器 | 單一請求速度 | 總輸出吞吐量 |
|---|---|---|---|
| gpt-oss-120b | 整張 H100 #0 | 120–180 tok/s | ~2,000 tok/s |
| Qwen3-30B-A3B | H100 #1 的 65% | 150–200 tok/s | ~1,800 tok/s |
| gpt-oss-20b | RTX 5090 的 60% | 200–260 tok/s | ~1,500 tok/s |

**每月營收（假設平均利用率 30%，輸入:輸出 = 3:1，不計快取折扣）**：

- H100 #0：2,000 tok/s × 30% × 2.59M 秒 ≈ 15.5 億輸出 token → $1,120；輸入 46.6 億 → $840。**小計約 $1,960**
- H100 #1：Qwen3 輸出 14 億 → $840、輸入 42 億 → $630；Qwen2.5-VL 約 $100。**小計約 $1,570**
- RTX 5090：gpt-oss-20b 輸出 11.7 億 → $350、輸入 35 億 → $245；BGE 與 Whisper 約 $100。**小計約 $700**
- **合計約 $4,230 / 月 vs. 成本 $2,550–3,150 → 損益兩平點約落在 18–22% 平均利用率。**

5090 每月只增加約 $250 成本，卻能接走小模型流量、讓 H100 #1 多出約 20% 的 Qwen3 容量，是划算的加購。
實際上白天尖峰、夜間離峰，要靠批次 API 把夜間算力填滿。

**容量上限提醒**：整套大約能支撐 60–120 個同時在線的聊天用戶或每天數百萬次短請求。超過時：
1. 速率限制回 429，並在控制台引導改用批次 API；
2. 小模型流量優先擴充 RTX 5090（便宜），大模型流量才擴充 H100。
