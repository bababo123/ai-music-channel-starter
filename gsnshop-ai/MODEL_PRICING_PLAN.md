# GSN AI 推論服務：2× H100 模型配置與定價規劃

> 目標：在 gsnshop.amaryllo.us 加入類似 fireworks.ai 的「預付儲值 → 依 token 計費」AI API 服務。
> 硬體：2 張 NVIDIA H100 80GB（以 SXM 估算；若為 PCIe 版，吞吐量約打 7–8 折）。
> 本文的吞吐量為依公開 benchmark 推估的數字，上線前需用 vLLM `benchmark_serving.py` 實測後再校正價格。

## 1. 設計原則

1. **只放 MoE 或小模型當 Serverless。** 2 張卡無法承載 DeepSeek-V3/R1（671B）、Qwen3-235B 這類大模型。
   MoE 模型（gpt-oss-120b 每 token 只啟用 5.1B、Qwen3-30B-A3B 只啟用 3B）在單卡上就有很高的並發吞吐量，最划算。
2. **每張卡獨立服務，不做 tensor parallel。** 單卡放得下的模型就不跨卡，故障時只影響一半的模型，也比較好排程。
3. **常駐、無冷啟動。** 模型數量少但全部常駐，Playground 和 API 第一個請求就很快。
4. **只賣 Serverless token。** 不出租整張 GPU，也不提供微調，兩張卡全部用來服務共享的 API 流量。

## 2. GPU 配置

| GPU | 服務 | 量化 | 權重 | 分配記憶體（含 KV cache） |
|---|---|---|---|---|
| GPU 0 | gpt-oss-120b | MXFP4（原生） | ~61 GB | ~72 GB（`--gpu-memory-utilization 0.90`） |
| GPU 0 | whisper-large-v3-turbo（faster-whisper / CTranslate2） | FP16 | ~1.6 GB | ~3 GB |
| GPU 1 | Qwen3-30B-A3B-Instruct-2507 | FP8 | ~31 GB | ~40 GB（0.50） |
| GPU 1 | gpt-oss-20b | MXFP4 | ~13 GB | ~20 GB（0.25） |
| GPU 1 | Qwen2.5-VL-7B-Instruct | AWQ 4-bit | ~6 GB | ~10 GB（0.12） |
| GPU 1 | BGE-M3 + BGE-Reranker-v2-M3（HF TEI） | FP16 | ~2.3 GB | ~4 GB |

- 推論引擎：vLLM（OpenAI 相容），前面放一層 API Gateway 做金鑰驗證、速率限制與計費（建議 LiteLLM Proxy 或自寫 FastAPI + Redis）。
- GPU 1 上多個 vLLM 行程共用同一張卡，靠 `--gpu-memory-utilization` 切分記憶體；也可以改用 MIG（H100 最多 7 個切片），隔離更好但配置較死。
- Qwen3-30B 的上下文先限制在 64K、gpt-oss-20b 限制在 32K，避免單一長請求吃光 KV cache。

## 5. 容量與損益估算

**成本假設**：H100 一張購入約 US$25–30K，3 年攤提，加上電費（~700W × PUE 1.4）與機房費用，全包約 **US$1.6–2.0 / GPU 小時**，
2 張卡每月約 **US$2,300–2,900**。

**吞吐量估計（vLLM，高並發，單卡）**：

| 模型 | 單一請求速度 | 整卡/分配後總輸出吞吐量 |
|---|---|---|
| gpt-oss-120b（整張 GPU 0） | 120–180 tok/s | ~2,000 tok/s |
| Qwen3-30B-A3B（GPU 1 的 50%） | 150–200 tok/s | ~1,500 tok/s |
| gpt-oss-20b（GPU 1 的 25%） | 200–260 tok/s | ~1,000 tok/s |

**每月營收（假設平均利用率 30%，輸入:輸出 = 3:1，不計快取折扣）**：

- GPU 0：2,000 tok/s × 30% × 2.59M 秒 ≈ 15.5 億輸出 token → $1,120；輸入 46.6 億 → $840。**小計約 $1,960**
- GPU 1：Qwen3 輸出 11.7 億 → $700、輸入 35 億 → $525；gpt-oss-20b 與其他約 $300。**小計約 $1,500**
- **合計約 $3,500 / 月 vs. 成本 $2,300–2,900 → 損益兩平點約落在 20–25% 平均利用率。**

利用率到 50% 時月營收約 $5,800。實際上白天尖峰、夜間離峰，要靠批次 API 把夜間算力填滿。

**容量上限提醒**：2 張卡大約能支撐 50–100 個同時在線的聊天用戶或每天數百萬次短請求。超過時：
1. 速率限制回 429，並在控制台引導改用批次 API；
2. 擴充第 3、4 張卡，或把溢出流量轉給外部推論商（需告知客戶）。
